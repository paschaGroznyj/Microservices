## Требования к инструменту по созданию знаний для БЗ РМ

### Общие требования

#### Цель разработки инструмента

Автоматизация процесса сбора, фильтрации и агрегации актуальных информационных материалов из открытых интернет-источников с последующим формированием дайджестов по запросам пользователей.

#### Пользователи инструмента

Целевая аудитория: участники Центра компетенций по Process Mining, ответственные за сбор, анализ и публикацию материалов, связанных с методологией, инструментами и опытом применения методологии Process Mining в различных сферах деятельности.
Всем заинтересованным пользователям.

---
### Функциональные требования
#### Основные функции инструмента

1. Сбор и обработка информации

а. Автоматический сбор информации: инструмент с заданной регулярностью запрашивает данные (материалы статей, исследований и пр.) от источника (интернет-ресурс, на котором размещены материалы исследований, практический опыт применения методологии и инструментов Process Mining), используя настроенные фильтры (ключевые слова, категории), сохраняет данные в Базу знаний (БЗ), формирует обзор добавляемого материала и размещает в БЗ.

Источниками сбора информации являются:

	https://arxiv.org - готово

	https://www.researchgate.net – парсер реализован, но пока не внедрен, т.к. нет кода, а разработчик в отпуске до 4 февраля

	https://ieeexplore.ieee.org  - у данного ресурса есть API, чтобы им воспользоваться надо зарегистрироваться на портале для разработчиков: https://developer.ieee.org/ Там же есть документация по API. Поскольку у этой библиотеки есть материалы с открытым доступом, предположительно, возможно хотя бы их получится получать через API, без платных подписок. При регистрации на портале разработчиков был отправлен запрос на API key, но к сожалению, запрос с прошлого в статусе ожидания, вероятно его так и оставят, либо позже отменят.
Можно парсить статьи с открытым доступом через Selenium, но т.к. они большие прикладные и научные, имеют много иллюстраций, таблиц и математические формулы, на данный момент принято решение отказаться от парсинга данного сайта

	https://scholar.google.com - готово

	https://fluxicon.com - готово
Регулярность обращения к источникам: инструмент имеет возможность настройки расписания обновления данных (ежедневно, еженедельно, ежемесячно и др.).
Определение ключевых критериев отбора публикаций: слова-маркеры, названия организаций, авторов, конференций.

б. Обработка данных источника: инструмент, по ключевым словам, находит информацию в источнике [анализирует материал на предмет соответствия тематике Process Mining], сохраняет в виде, пригодном для размещения в Базе знаний, дальнейшей обработки и визуализации, и размещает итоговый материал в Базе знаний (cloud.ru) [в соответствующем разделе онтологии].

2. Формирование дайджеста в заданном формате (Приложение)

а. Дайджест по всем материалам Базы знаний (БЗ): инструмент формирует обзор всех материалов, содержащихся в БЗ по запросу пользователя.

б. Дайджест по тематическим материалам Базы знаний (БЗ): инструмент формирует обзор всех материалов, относящихся к заданной пользователем тематике.

в. Дайджест по материалам Базы знаний (БЗ) за период: инструмент формирует обзор всех материалов, добавленных в БЗ за заданный пользователем период.

3. Формирование обзора в заданном формате (Приложение)

а. Обзор материала Базы знаний (БЗ): инструмент формирует обзор добавляемого в БЗ материала. 

4. Дополнительный функционал

Настройка временных рамок: возможность выбирать временной период для формирования дайджеста (за последнюю неделю, месяц, конкретный период).
Группировка материала: структурированная подача результатов (по категориям, ключевым словам, источникам, популярности).
Фильтрация дубликатов: исключение повторяющихся статей, новостей и ссылок.
Оценка релевантности: ранжирование полученных данных по степени соответствия запросу пользователя. 
Формат вывода результата: подготовка дайджеста и обзора в удобочитаемом виде (текстовый файл, PDF-документ, HTML-страница, email-письмо) Приложение.

4. Корректировка материалов в БЗ: инструмент позволяет производить корректировку и материалов БЗ при выявлении ошибок в информации.

5. Пользовательский интерфейс

Взаимодействие с инструментом: взаимодействие пользователя с инструментом производится через интерфейс в виде чата: строка для ввода текста запроса, кнопка запуска.

#### Дополнительные функции

Уведомления: отправка дайджеста автоматически на электронную почту пользователя после завершения формирования.
Анализ трендов: предоставление статистики и аналитической информации о популярных материалах, источниках и тенденциях в рамках выбранной темы.]

#### Нефункциональные требования

Масштабируемость: способность расширять функциональность без потери производительности.

Совместимость: поддержка работы с различными операционными системами и браузерами.

Обновляемость: регулярное обновление программного обеспечения для улучшения качества предоставляемых услуг и устранения возможных уязвимостей.

Производительность: инструмент должен обрабатывать материалы за разумное время (не более 5 минут на один материал).

Конфиденциальность: категорийность информации обрабатываемой инструментом - не выше К-4.

## Название статьи
The Role of Log Representativeness in Estimating Generalization in Process Mining

## Авторы  
Anandi Karunaratne, Artem Polyvyanyy, Alistair Moffat

## Ссылка на источник  
https://www.researchgate.net/publication/384899235_The_Role_of_Log_Representativeness_in_Estimating_Generalization_in_Process_Mining

## Описание
### 1. Цель  
Изучить влияние репрезентативности логов на точность оценки обобщения при моделировании процессов, полученных в результате PM-анализа.

### 2. Проблема  
При отсутствии явных описаний реальных систем качество модели процесса зависит от качества исходных данных (логов событий). Репрезентативные логи непосредственно отражают процесс, тогда как менее репрезентативные требуют дополнительной обработки, что может привести к искажениям.

### 3. Задачи  
- Разработать простую аппроксимацию репрезентативности лога.
- Исследовать взаимосвязь между репрезентативностью лога и точностью оценки обобщения.
- Оценить эффективность применения методов бутстрэп для повышения точности оценки обобщения.

### 4. Подход
Используется метод бутстрэп для оценки обобщающей способности модели процесса. Лог событий рассматривается как выборка поведения системы, а затем генерируются дополнительные логи путем случайного отбора и "скрещивания" существующих путей. Это позволяет оценить степень соответствия модели реальному поведению системы.

### 5. Как реализуется подход  
Процесс включает два этапа:
1. Генерация множества бутстрэп-логов из исходного лога с использованием метода Log Sampling With Breeding (LSMbr).
2. Вычисление меры обобщения для каждого бутстрэп-лога и усреднение результатов для получения окончательной оценки.

### 6. Оценка результатов  
Предложен простой способ оценки репрезентативности лога (Trace-Based Log Representativeness Approximation, TLRA), который демонстрирует высокую корреляцию (99,43%) с существующими методами оценки репрезентативности.

### 7. Вывод  
Степень репрезентативности лога существенно влияет на точность оценки обобщения. Высокорепрезентативные логи позволяют напрямую использовать их для оценки, тогда как низкорепрезентативные требуют дополнительной обработки, например, с помощью метода бутстрэп.
