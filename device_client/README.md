# Device Bridge — настольный клиент

Минимальное окно Tkinter с английскими подписями для подключения устройства к
Device Bridge. Поддерживается **только `ping`**: проверка связи возвращает `pong`,
это не системный ping и не запуск программы. Shell, PowerShell-команды, доступ к
файлам и произвольное выполнение кода отсутствуют. Скрипт PowerShell ниже —
только локальный запуск приложения, не исполнитель удалённых команд.

**Windows пока не проверен на реальной системе.** Нужна отдельная проверка
запуска, буфера обмена, TLS, отключения и закрытия окна на целевой Windows.

## Подготовка и запуск на Windows

1. Самостоятельно установите Python **3.10+** с компонентами **Tcl/Tk**, `venv`
   и `pip` (обычный установщик Python для Windows). Проверьте `py -3 --version`
   либо `python --version`. Администратор для самого клиента не требуется.
2. Скопируйте каталог `device_client` целиком, включая `core.py`, `desktop.py`,
   `requirements.txt` и `start-windows.ps1`. Не копируйте в него токен или файл
   с секретами. Перейдите в этот каталог в PowerShell:

   ```powershell
   .\start-windows.ps1
   ```

   Launcher сначала проверяет **`py -3`**, затем **`python`**; используется первый
   подходящий Python 3.10+. Если `py -3` выбирает старую версию, проверяется
   `python`, другие версии launcher не перебирает. Python автоматически не
   устанавливается. Окружение создаётся в `%LOCALAPPDATA%\DeviceBridge\venv`;
   если переменная отсутствует или каталог создать нельзя — в `.venv` рядом
   со скриптом. Окружение повторно используется, активация не нужна.
   Старое/повреждённое окружение можно удалить отдельно и повторить запуск.
   На каждом запуске `pip` устанавливает точные зависимости из файла:
   **`websocket-client==1.8.0`**. Для первой установки нужен доступ к индексу pip.
3. Если политика организации запрещает `.ps1`, launcher ничего не меняет:
   не отключает execution policy, не требует повышения прав и не обходит
   ограничения. Используйте разрешённую организацией процедуру или ручной
   запуск ниже. Не передавайте токен в командной строке.

Ручной вариант без запуска `.ps1` и без активации окружения (из `device_client`;
если `py` отсутствует, замените `py -3` на `python` 3.10+):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe desktop.py
```

Из корня репозитория также можно запустить установленным Python:
`python -m device_client.desktop`. Tkinter входит в установку Python, это не
пакет pip. На Linux для локальной проверки нужны системные Tcl/Tk и дисплей
(либо Xvfb); launcher предназначен только для Windows.

## Токен и подключение

1. В браузере войдите в приложение на том же доверенном HTTPS-домене.
   Нужен **device token**, уже выданный при регистрации устройства через
   `POST /api/devices` (например, имя ПК и `platform: "windows"`). Изменяющие
   HTTP-запросы требуют `X-Device-Bridge: 1` и браузерную аутентификацию;
   подробности — в `api_gateway/docs/device-bridge.md`.
2. Значение `token` возвращается **только один раз в ответе регистрации**.
   Список устройств его не возвращает. Окно не регистрирует устройство и не
   получает токен из браузера автоматически. Если уже выданный токен потерян,
   отзовите старое устройство и зарегистрируйте новое; это не восстановление
   прежнего токена. Не используйте login/SSO-токен, cookie или `device_id`.
3. Оставьте `Server URL`: **`https://augent.uva-advanced.ru`**, если используется
   этот сервер. Для другого сервера укажите доверенный базовый URL;
   нормализацию и проверку выполняет `core.py`. Не вставляйте секрет в URL.
   Вставьте только значение device token, без JSON, кавычек и префикса `Bearer`,
   через **Paste** или Ctrl+V. **Clear** очищает поле. Токен всегда замаскирован.
4. Нажмите **Connect**. Возможные состояния: **Connecting**, **Online**,
   **Reconnecting**, **Stopped**, **Unauthorized**. `Unauthorized` означает,
   что следует проверить срок действия/отзыв токена и серверную авторизацию;
   бесконечного автоматического повтора после терминальной ошибки нет.
   Временные сетевые сбои и повторные подключения обрабатывает core.
5. При `Online` отправьте из авторизованного браузера
   `POST /api/devices/{device_id}/commands` с телом
   `{"operation":"ping","timeout":10}` и `X-Device-Bridge: 1`.
   Ожидаемый результат — `pong`. В окне нет ввода или запуска команд.
6. **Disconnect** запрашивает остановку. Пока предыдущие рабочие потоки не
   завершились, **Connect** недоступна, даже если статус уже `Stopped`.
   Для нового подключения вставьте токен заново: поле очищается сразу после
   успешного создания клиента. Закрытие окна вызывает остановку и опрашивает
   завершение без блокировки GUI, максимум около **4 секунд**; зависшие
   daemon-потоки не удерживают процесс. Отключение не отзывает токен;
   отзыв — `DELETE /api/devices/{device_id}` из авторизованного браузера.

## WSS и сервер

Публичный адрес WebSocket по умолчанию:
**`wss://augent.uva-advanced.ru/api/devices/connect`**. Соединение использует
`Authorization: Bearer <device token>`, не query string и не браузерные cookies.
TLS-проверку отключать не нужно. При ошибках сертификата исправьте цепочку
доверия/настройки сервера, а не обходите проверку.

Для main gateway nginx должен направлять **точный location
`/api/devices/connect`** на **`http://127.0.0.1:7000`** (либо
`http://api_gateway:7000` внутри закрытой Docker-сети) с HTTP/1.1 и заголовками
`Upgrade` / `Connection`. Именно для этого location отключается браузерный
SSO-redirect, сохраняется `Authorization` устройства, удаляются cookies и
недоверенные identity-заголовки. Остальные `/api/devices` остаются за обычной
браузерной аутентификацией. Клиент подключается к публичному HTTPS/WSS-порту,
**не к открытому в интернет порту 7000**. Конфигурация и границы доверия описаны
в серверном руководстве; его пример через Sigma использует **7010**, не 7000.
Окно не меняет nginx, firewall или сервер. Одно устройство не следует подключать
двумя клиентами одновременно; второй сеанс сервер может отклонить.

## Секреты и ограничения

- Токен существует только в оперативной памяти, не записывается в настройки,
  файлы или журнал. Очистка поля не является гарантией обнуления памяти Python.
  После подключения токен нужен core в памяти для повторных соединений.
- **Paste** читает системный буфер обмена, но не очищает его. Очистите его сами,
  учитывая историю и синхронизацию Windows Clipboard. Не делайте снимков токена
  в браузере и не отправляйте дампы регистрации/заголовков в поддержку.
- В окне только очищенные события core; исключения конструктора и worker не
  выводятся целиком. Дополнительно маскируется совпадение с переданным токеном.
  Журнал хранит не более **300 строк**, по **1000 символов** на событие;
  очередь ограничена **500 событиями**, старые события при переполнении теряются.
  **Clear log** очищает окно; файлы журнала не создаются.
- Нет автозапуска, фоновой службы, установщика, сохранения URL/токена,
  автоматического обновления или средств администрирования Windows.

## Контракт с `core.py`

`BridgeClient(server_url, token, on_event=callback)` создаётся в GUI-потоке:
конструктор проверяет и нормализует URL/токен, при ошибке выдаёт `ValueError`.
Синхронный `client.run()` вызывается в отдельном daemon-потоке и работает до
остановки или терминальной ошибки авторизации/протокола. Thread-safe
`client.stop()` вызывается отдельным daemon-потоком, чтобы даже медленная
остановка не замораживала окно. Callback имеет вид `callback(kind, message)`:
`kind` — `status`, `log` или `error`, сообщения уже очищены core;
статусы — `connecting`, `online`, `reconnecting`, `stopped`, `unauthorized`.
Callback пишет только в ограниченную `queue.Queue`; все операции Tk выполняет
GUI-поток через `root.after`. Других методов или внутренних полей core UI не
использует. Core использует `websocket.create_connection` и
`websocket.WebSocketTimeoutException` из `websocket-client`, не пакет `websocket`.

### Уточнения первой версии

- Это исходный Python/Tk-клиент, **не готовый EXE**. Установщик, автозапуск,
  системная служба и безопасное постоянное хранилище credentials пока не реализованы.
- Системное время Windows должно быть синхронизировано: клиент отвергает задания,
  дедлайн которых уже прошёл по локальным часам.
- Disconnect прерывает активный сокет. На стадии DNS/TCP/TLS соединения остановка
  может ждать завершения сетевой операции; закрытие окна ограничено четырьмя секундами.
- 401/403 при подключении — окончательный отказ, но не обязательно плохой токен:
  возможны занятое устройство или неправильная настройка ingress. Для ручного
  повторения вставьте токен снова; отзыв не обходится автоматической регистрацией.
